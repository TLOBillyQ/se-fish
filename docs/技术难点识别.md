## 高风险：存在能力缺口或无法在试玩中验证

### 1. 非人形鱼 / 首领的模型与动画

- 需求：14 种精英鱼与首领全部非人形（鳗、蟹、三头鲨、翼龙、20 米哥斯拉），各有专属移动与攻击动作。
- 官方 `AnimatedUnit` 页明说："当前官方预设资源列表没有可直接用于作者验证的 AnimatedUnit，普通'带动画外观'的预设也可能仍是 WorldUnit"，并把它定位为"机关、装饰物等非角色对象"（`<站点>/game_api/unit/AnimatedUnit.html`）。编辑器子组件限制表里也没有 `AnimatedUnit` 一行（`<站点>/scene_editor/unit.html`）。
- 自定义模型导入只有"导入角色（人形骨骼）"，导入时校验骨骼节点命名（`<站点>/customfile.html`）。非人形带动画 FBX 能否导入，文档没有描述。
- 官方模型库有成批**静态**鱼模型：7000544–7000563（大马哈鱼、旗鱼、鲨鱼、鳐鱼、螃蟹、食人鱼等）、50227 s9_翼龙、6000019 章鱼、57349 鱼群（`<站点>/assets/model.html`）。无鳗、哥斯拉、三头鲨。目录不标注是否带动画；动作目录全是角色动作。
- `AnimatedUnit : WorldUnit`（`:5040`）不带 Controller，没有 `Health` / `TakeDamage` / `MoveTo` / `Died`。鱼的血量、受击、移动、仇恨全部自研。
- 默认方案：静态模型 + Tween / Motor 程序动画，或用 `EggyUnit` / `HumanUnit` + `Animator` 承载人形 / 蛋形怪物；首领模型需自制。唯一值得一试的是上传一个带内置动画片段的非人形 FBX，看导入校验是否放行。

### 2. 鱼的移动与 AI

- 能力：`PathfindingService`（`HasNavMesh` / `HasDynamicNavMesh` / `CreatePath{AgentRadius, AgentCanClimb}`）、`PathfindingLink`。
- 缺口：导航网格只解决地面行走。飞行（白头鹰、风神翼龙 20 m/s）、跃起落点 AOE、绕岛巡航后跃出咬人并叼走玩家（沧龙）、随机翻滚都要自写轨迹。"撞墙转 90°""触水即消失"需自写检测。
- 性能：逻辑帧 30 Hz，鱼由服务端逐帧驱动；8+ 玩家 × 每人多条上岸的鱼，需做数量上限与追踪降频。

### 3. 水体判定

- 需求：抛竿落点在不在水里；鱼逃到水里消失；空气墙挡游泳。
- 已定论不支持：`RaycastResult` 只有 `Distance` / `Instance` / `Normal` / `Position`（`:1939-1944`）；Water 只是材质参数（`:1032-1124`）；`ControllerStateType.Swimming` 只针对角色自身。
- 方案：每个钓鱼区配置水面高度 + 水域 `TriggerUnit`（或多边形数据），落点与鱼的位置自行判定。场景里的"水"是什么单位、射线能否命中它，需在编辑器内看。

### 4. 付费闭环（金豆 / 乐园币 / 广告 / 盲盒）

- 能力：`CommodityService`（17 函数 / 5 事件，`:3925-4040`）；`AdvertisementService:ShowRewardedVideoAd(player, goodsId, successEvent, failEvent, adTag)`（`:3607`）；邮件系统可发"游玩奖励"类商品。
- 难点：
  - **无订单 ID**：`GoodsPurchaseCompleted(goodsId, goodsNum, player)` "当前没有公开订单 ID"，官方教程明说不能用 `UserId..goodsId` 做发货防重键（`<站点>/lua/20-platform-services.html`）。在服务端监听该事件发货，幂等要自己设计。
  - **购买无取消 / 失败回调**：5 个事件里没有，`ShowGoodsPurchasePanel(player, rawGoodsId, showTime)` 返回 void。"支付期间暂停复活倒计时，取消后恢复"没有事件可挂，只能超时兜底。`showTime` 的语义未说明，需实测。
  - **广告在编辑器内不可验收**：须服务端调用；编辑器 / 本地调试"可能无回调、无 UI 表现或直接静默失败"（`<站点>/game_api/service/AdvertisementService.html`）。`failEvent` 也不保证触发，同样要超时兜底。
  - `goodsId` 来自商业化后台，后台文档不在公开站点。API 无价格 / 货币 / 盲盒 / 抽奖接口，盲盒的随机与发奖只能写 Lua，支付环节才可能走商品。
  - 盲盒用金豆还是金币在策划案里自相矛盾（见 `to-questionnaire-策划案内部矛盾.md`）。
  - 需要一张已发布的测试图。MemoryStore 明文未发布不可用（`UnpublishedPlace=102`，`:3263`）；DataStore 错误码无"未发布"项，教程默认测试地图可真实读写（推断）；商品未查到。

### 5. 存档体积与可靠性

- 能力：`DataStoreService`（`GetDataStore` / `GetGlobalDataStore` / `GetOrderedDataStore`，`UpdateAsync` CAS，版本历史），全异步，须在 `Task:Spawn` 内调用；`game:BindToClose` 关服前留 30 秒。官方 fishing-demo 的做法：`pcall` 重试 + 会话锁 + 30 秒自动存档 + Attribute 同步客户端。
- 难点：
  - 物品不叠加，每条鱼带个体倍率与烤制倍率；道具栏 8 + 背包 40 + 盲盒"不受背包上限"→ 单键体积无上界。需要紧凑编码，并给盲盒溢出设硬上限。
  - `ValueTooLarge=123` 与四层限流错误码（单局队列 / 单键 / 单服务器 / 全服务器）都无数值（`:2932-3002`）；官方页只说"写入有频率限制"，且普通 `GetAsync/SetAsync` 不直接返回错误码，只能靠 `pcall` 的错误信息。写入必须合并、排队。有数值的只有：名称 / 键 ≤ 50 字符、`PageSize` 1–100、元数据值 ≤ 250 字符。
  - 离线续存项多：所在钓鱼区与坐标、濒死 / 死亡标记、虚弱剩余时间、药水次数、图鉴最大重量、新手任务进度。
  - 0917 新增 `Game.ServerRestartScheduled`，与常驻房间的存档时机直接相关，本地声明尚未包含。

## 中风险：有能力，但实现量大或有坑

### 6. 全服纪录

可行。`OrderedDataStore:GetSortedAsync`（`:1666`）即排行榜用途，**值必须为整数**（错误码 411，`:2998`），鱼重量需放大取整后存。问卷里"未找到跨房间共享数据接口"的判断已过时，应更新。难点在约 100 种鱼的键设计、写限流，以及跨服务器刷新（`MessageService:PublishAsync`，单条 ≤ 1 KB，尽力而为不保证送达）。

### 7. 玩家状态改造

- 濒死锁血：原生 `Health` 归零即触发 `Died`。300 点血、锁 1 血、无敌、15 秒抢救都要自管血量，不让原生 `Health` 归零；原生血条用 `CoreGuiType.Health` 关掉。API 无"自动复活开关 / 复活延时 / 无敌"字段，只有 `Players.CharacterAutoLoads`、`Reborn()`、`SetStateEnabled`（能否禁 `Dead` 未说明）。自动复活可能由编辑器【规则 → 死亡规则 / 复位规则】控制（推断，`<站点>/rules/rules.html` 只列了标题）。
- PK 区 / 安全区 / 小队免伤：`TakeDamage(damage)` 无来源参数，脚本伤害无原生过滤（`:5235-5365`），统一走服务端判定。阵营不适合运行时小队：`Camps:SwitchPlayerCamp` 已于 0723 废弃，`AssignCamp` 于 0805 删除。官方技能系统有 `TargetFilterCamp`（0 不限 / 1 敌方 / 2 友方），但阵营本身静态。`Player:GetPartyId()`（`:6643`）可识别进图前的组队，图内临时组队自研。
- 变大药水：`EggyUnit:SetScale` 存在（`:6113`）。注释只写"设置缩放"，不像 `HumanUnit:SetScale` 写明影响碰撞体积；3 倍体型下碰撞、相机、挂点、举鱼位置需验证。
- 风神之翼：`GravityEnabled = false` + `ApplyForce`，自写 20 米限高与缓降。
- 哥斯拉变身：`EggyAppearance:SetAppearanceByAssetId` 只接生物预设（`:958`）；自定义外观走 `CustomAppearanceService`，须在服务端执行才全端可见。

### 8. 举鱼

- 首选原生抓举：把鱼做成动态 `WorldUnit` 并设 `Liftable`（`:7317`），玩家省略参数调用 `Lift` 即"抓举身前的目标"（只有 `force_lift_unit` 参数限 `EggyUnit`，`:6054-6056`）。`EggyController.OnLiftBegin` 官方明说可能不触发，改听物体侧 `WorldUnit.OnLiftedBegin` / `OnLiftedEnd`（`:7333-7334`，是否同样受影响未查到）。技能包里 `1v1-arena-demo.md` 仍把 `OnLiftBegin` 当业务入口，不要照搬。
- 备选：把鱼设为玩家 `EggyUnit` 的子节点 + `ModelBindParent`。子组件限制表允许 `WorldUnit` / `RenderUnit` / `TriggerUnit` / `EffectUnit` 挂在 `EggyUnit` 下；运行时改 `Parent` 是否等效需验证。
- 不可行或不推荐：`Attachment` 只能挂在 `WorldUnit` / `Attachment` 下，不能挂在 `EggyUnit` 下；`RigidConstraint` 官方页明示动态创建有弹性连接、固定异常等问题；`WeldConstraint` 自 0820 起可在服务端创建时传 `ConnectUnitList`（`:7286-7295`，创建后不可改），但类型是 `BasePart[]` 而 `EggyUnit` 是 `SpaceUnit`，能否焊到蛋仔本体需实测。

### 9. 高频输入

冲锋枪 0.1 秒连发、收线狂点，都是每人每秒约 10 次 RemoteEvent。频率与包大小上限在本地注释、官方页、教程里都没有数值；每次只能带一个 payload，且不支持直接传 `CFrame`（`:1995-2021`）。客户端按时间窗聚合，服务端用 `World:GetServerTime()` 校验 CD 与次数上限，命中用服务端 `PhysicsService:Raycast`（目标须 `CanQuery` 且碰撞组允许）。

### 10. 摆渡

`SeatUnit` / `Seated` 状态存在；"站在船上被带走"依赖物理摩擦，不可靠。建议倒计时结束时把船上 Trigger 内的玩家直接传送，船只做表现。`TeleportService:TeleportAsync(mapId, players)` 是跨地图传送，可作"七区拆成多张图"的退路，但会拆散同房玩家，搭便船与返程的语义要重做；`ChangeServerAsync` 等跨服接口在编辑器内返回 false / nil，不可测。

### 11. 单图七区的规模

整图容量、单位总数上限无数值：只有同级子组件上限（多为"不限"）与资源大小（图片 ≤ 3 MB、1920×1080，音频 ≤ 1 MB / 60 秒）。平台提供 AOI / Streaming（`World.AOIType`、`StreamingMainRadius`、`BasePart.Persistent`，0820 / 0917 日志）。常驻房间里"丢弃物永不消失"是无界增长，必须加总量上限与回收。场景用 `IsStaticOptimization`，注意标记后脚本查不到该单位。

### 12. 常驻房间

世界模式模板支持，手册只有定性表述"随进随出、可容纳更多玩家"（`<站点>/newbie.html`）。0820 更新后【实时共建】多人试玩支持其他玩家随时加入。房间人数上限无数值（API 无 `MaxPlayers`；`SpawnLocationUnit.Capacity` 是单个出生点容量），可能在编辑器【规则 → 匹配和匹配参数规则 / 乐园岛匹配规则】里配（推断）。

### 13. 分享任务按钮

当前公开 API 不支持。`SocialService` 只剩队伍查询（`:4585-4600`）；`PromptGameInvite` / `PromptLinkSharingAsync` 及其事件在 0723 日志中废弃，官方教程明说"不要照搬旧示例中的分享或邀请函数名"。需改设计或向官方申请。

## 低风险：有直接对应能力

| 需求 | 能力 |
|---|---|
| 鱼线 | `LinkEffectUnit.EndPosition` + 官方特效 5379"连线-绳子"，客户端逐帧更新终点；0827 新增 `EndBindUnit` |
| 头顶文字泡、NPC 交互 | `SceneGui` 把 EUI 节点挂到单位插槽；无 ProximityPrompt，距离检测自写 |
| 血量球 / 饥饿球 | `EUIProgressTimer` 环形进度 |
| 背包拖拽 | `EUINodeBase` 的 `OnTouchMoved` 等触摸事件自实现拖放 |
| 隐藏原生按钮（举起、滚动、背包、血条） | `CoreGuiType` |
| 通关成就 | `ArchiveService:SetAchievementProgress` / `AchievementComplete` |
| 开场对话 | 剧情对话编辑器 / `StoryService` |
| 鱼、武器手持挂接 | `EggyAppearance:BindAppearance`（`:911`，骨骼挂点挂外观件），或 `WorldUnit` 作为 `EggyUnit` 子节点；不要用 `Attachment`（见 §8） |

原生 `Backpack` / `Tool` 类存在，但"不叠加 + 个体倍率 + 拖拽 + 双栏"与其模型不符，物品系统建议自研。

## 建议先做的验证原型

1. 非人形带动画 FBX 导入（预期偏悲观，失败即按程序动画定美术管线）。
2. 水判定：水面高度 + Trigger，配合抛竿落点。
3. 濒死锁血与原生 `Died` / 复活流程的冲突；顺带看【死亡规则】【匹配规则】面板字段。
4. 举鱼：`Liftable` 的 `WorldUnit` 被原生抓举，及 3 倍缩放下的表现。
5. 发布一张测试图，验证 DataStore 阈值、商品购买、激励广告的真实回调。
6. 8 人 + 约 20 条活鱼 + 连发武器的服务端压测。
